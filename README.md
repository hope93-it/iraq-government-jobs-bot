# بوت التعيينات الحكومية العراقية 🇮🇶

مشروع Python يعمل بمهمة GitHub Actions كل نصف ساعة تقريباً، بدون تشغيل حاسبتك. واجهته عربية، ومخصص حالياً لصاحب Chat ID واحد. لا يستخدم API ذكاء اصطناعي مدفوع؛ الفرز يعتمد قواعد لغوية محافظة، وله احتمال يفوّت إعلان أو يحتاج تعديل. لا توجد وسيلة تضمن اكتشاف كل تعيين حكومي.

**حالة التسليم: الكود والاختبارات جاهزة. لم يربط بحساب GitHub أو بوت فعلي بعد؛ تحتاج تسوي خطوات الإعداد أدناه. التغطية الفعلية المفعلة حالياً للبصرة فقط. دعم جميع المحافظات موجود في الفرز والأوامر، لكن التغطية الوطنية غير مكتملة لأن المصادر الوطنية المفحوصة متعطلة/محجوبة.**

## شلون يشتغل؟

1. يقرأ `robots.txt` ويحترم النطاقات والمسارات المسموحة. فشل الوصول أو CAPTCHA يوقف ذلك المصدر فقط. لا يوجد تغيير هوية للالتفاف على الحماية.
2. يقرأ أول صفحة/حد الروابط المحدد لكل مصدر. هناك محولات HTML وRSS وAPI JSON، لكن المصادر المفعلة تستخدم HTML فقط لأن هذا ما تم التحقق منه. لا يفترض أن المواقع تملك RSS أو API.
3. يجلب النص والتاريخ، ويقرأ حتى مرفقين PDF نصيين من النطاق المعتمد. الحد 12MB و40 صفحة لكل PDF. المرفقات المصورة تحتاج OCR غير مشمول؛ تظهر ملاحظة عند تعذر القراءة ولا يخترع محتواها.
4. يحتاج كلمات تدل على وظيفة وتقديم مفتوح. يستبعد أنماط نتائج القبول والمناقصات وبعض أخبار التعيين الإداري. العنوان يستعمل كعنوان الإعلان؛ لا يخترع اسم وظيفة أدق منه. المؤهل والطريقة والموعد تُنقل كعبارة من النص، وإلا «غير مذكور».
5. يحفظ معرف المصدر+الرابط، وبصمة النص، وتوقيع جمل التقديم. يكتشف تغيرات المؤهل/الموعد/جمل التقديم في الإعلانات المعروفة. لا يعيد تنزيل المقالات غير الوظيفية التي بقي عنوانها نفسه؛ تعديل قديم يحوّل مقالاً عاماً إلى إعلان مع بقاء العنوان قد يفوت.
6. كل مصدر جديد يبدأ بتهيئة صامتة. لا ترسل إعلاناته الحالية. لا تكتمل تهيئته حتى ينجح المرور الأول؛ الفحص الجزئي يبقى صامتاً للمصدر.
7. الإعلان الجديد يحتاج تاريخاً رسمياً قابلاً للقراءة وعمره 0–7 أيام. المفقود/القديم يذهب إلى `review` بدون إشعار. هذا اختيار محافظ لتجنب الأخبار القديمة، وقد يفوّت إعلاناً جديداً بلا تاريخ. /today يعتمد وقت الاكتشاف بتوقيت بغداد.
8. يعطي البصرة أولوية ترتيب قبل بقية الإعلانات ثم أخبار القنوات. الإعلانات التي تنص على شمول كل المحافظات تظهر أيضاً في /basra.

توحيد الروابط يزيل وسوم التتبع. تطابق النص تماماً أو الرابط يمنع إعادة نشر مطابق عبر المصادر. إعادة صياغة إعلان قديم بالكامل ليست قابلة للكشف بيقين بهذا النظام؛ لا يوجد ادعاء أنه يفهم كل إعادة نشر. الصور وحدها أو ملفات PDF غير قابلة للاستخراج قد تفوت.

## التخزين ومنع التكرار

الحالة في `state.json` على فرع `bot-state` داخل نفس مستودع GitHub، وليست Actions artifacts أو cache. كل حفظ يكتب مباشرة باستخدام GitHub Contents API و`GITHUB_TOKEN` المؤقت بصلاحية `contents: write`.

- `concurrency` يمنع تزامن مهام المراقبة؛ `sha` يمنع الكتابة فوق حالة تغيرت.
- حالة الرسالة: `pending` ثم حفظ `sending` **قبل الاتصال بتيليگرام**؛ ثم `sent` بعد استلام `ok=true` و`message_id` وحفظهما.
- الرفض الصريح مثل 429 يعاد وفق التأخير المسموح، حتى خمس دورات إرسال. الأخطاء الشبكية أو الاستجابة غير الحاسمة تبقى `uncertain`، والانقطاع قد يتركها `sending`؛ الحالتان لا تعادان تلقائياً.
- **Telegram sendMessage لا يوفر مفتاح idempotency. ضمان عدم الفقد وعدم التكرار معاً غير ممكن إذا وصلت الرسالة وضاع الرد أو فشل الحفظ.** هذا المشروع يفضل تعليق الحالة الملتبسة للمراجعة على تكرار الإشعار. لذلك ليس ضمان exactly-once.
- راجع المحادثة، ثم افتح ملف الحالة بالفرع `bot-state` للحصول على مفتاح الحدث المعلق. شغّل workflow بنوع `resolve` واملأ `event_id`: اختر `sent` إذا الرسالة موجودة، أو `retry` بعد التأكد من عدم وصولها. لا يغير قرار `sent` الادعاء بأن API أكدها؛ حقل `resolution` يبين أنه قرار يدوي.
- لا تحذف الفرع ولا تصفر `offset` ولا تشغل نسخة ثانية بنفس التوكن. إذا الفرع موجود والملف مفقود يتوقف بدلاً من تصفير الحالة. استرجع الملف من سجل git.
- عندما يقارب JSON حجم 850KB يتوقف بأمان؛ احتفظ بالأرشيف وانقل السجل لاحقاً لقاعدة بيانات أو تخزين مقسم. لا نحذف بصمات الإعلانات تلقائياً.
- المستودع العام يجعل الكود وسجل الأخبار ومحتوى الأخبار المعلقة وأرقام تحديثات تيليگرام ومعرفات الرسائل علنية. التوكن وChat ID ليسا محفوظين في الحالة. للمحتوى الخاص استخدم مستودعاً خاصاً وراجع حصص التشغيل.

## خطوات التثبيت — اتبع وحدة وحدة

### 1. إنشاء البوت

1. افتح تيليگرام وابحث عن **@BotFather** الرسمي: https://t.me/BotFather . تأكد من الحساب الرسمي وعلامة التوثيق.
2. اضغط Start، وأرسل `/newbot`.
3. اكتب اسم العرض، مثلاً `تعيينات العراق والبصرة`.
4. اكتب يوزر متاح بالإنجليزية ينتهي بـ `bot`، مثلاً `AzuzIraqJobsBot` إذا متاح.
5. BotFather يعطيك Token. احتفظ به لنفسك؛ لا ترسله بالدردشة ولا ترفعه بملف. إذا انكشف استعمل `/revoke` داخل BotFather.
6. افتح رابط بوتك وأرسل `/start`. ما راح يجاوب قبل تشغيل المشروع، وهذا طبيعي.

**هنا وقف إذا نمشي سوا، واكتب «تم إنشاء البوت». لا ترسل التوكن.**

### 2. إنشاء مستودع GitHub ورفع الملفات

1. ادخل https://github.com/ وأنشئ حساباً إذا ما عندك.
2. اختر **New repository** وسمّه `iraq-government-jobs-bot`.
3. اختر Public لتستفيد من التشغيل المجاني على standard runners، مع فهم علنية السجل أعلاه. ممكن تبدأ Private لاستخراج Chat ID وتراجع الحصص قبل إبقائه خاصاً.
4. فك ملف ZIP على جهازك. ارفع **محتويات** مجلد المشروع إلى جذر المستودع، بحيث يظهر `bot.py` مباشرة ولا يكون داخل مجلد إضافي.
5. تأكد من رفع المجلد المخفي `.github/workflows`؛ بدونه ماكو مهام. من واجهة GitHub ممكن تنشئ `Add file → Create new file` وتكتب المسار `.github/workflows/monitor.yml` وتنسخ محتواه إذا جهازك يخفيه. ارفع `tests.yml` كذلك.
6. احفظ Commit على الفرع الافتراضي، عادة `main`.
7. من Settings → Actions → General تأكد Actions مسموح. المشروع يطلب `contents: write`؛ سياسات مؤسسة/حماية فروع قد تمنع إنشاء فرع `bot-state`، ويجب تعديلها إن كنت تملك الصلاحية. لا تحتاج Personal Access Token.

### 3. إضافة التوكن فقط أولاً

Settings → Secrets and variables → Actions → New repository secret:

- Name: `TELEGRAM_BOT_TOKEN`
- Secret: التوكن من BotFather.

القيم لا تدخل بملف Python ولا بسورس المشروع. لا تضف `.env` إلى المستودع.

### 4. استخراج Chat ID بدون موقع خارجي

الطريقة على GitHub، مناسبة إذا تستخدم آيفون وما عندك Python:

1. تأكد أنك أرسلت `/start` **لبوتك** برسالة خاصة وأن ماكو webhook أو نسخة بوت ثانية تعمل بنفس التوكن.
2. Actions → **مراقبة التعيينات** → Run workflow → mode=`get-chat-id` → Run.
3. افتح خطوة «تشغيل المراقبة». يطبع الاسم الأول وChat ID للمحادثات الخاصة التي أرسلت للبوت. اختَر رقم محادثتك بعد مطابقة الاسم، ولا تخمن إذا ظهرت أسماء متعددة. إذا ما ظهر رقم، أرسل رسالة جديدة وشغّلها ثانية.
4. لا يطبع التوكن. **سجل هذه الخطوة يحتوي معرف المحادثة واسمك**؛ في مستودع عام يمكن مشاهدته. احذف تشغيل الإعداد هذا من قائمة Actions بعد نسخ رقمك. لأعلى خصوصية نفّذ هذه الخطوة بمستودع خاص أو محلياً.
5. أضف Secret جديد باسم `TELEGRAM_CHAT_ID` وقيمته الرقم.

الطريقة المحلية البديلة، إذا عندك Python 3.12: `python -m pip install -r requirements.txt` ثم `python bot.py --get-chat-id`. يطلب التوكن بإدخال مخفي إذا مو موجود بمتغير البيئة. لا يحتاج موقعاً أو بوتاً لطرف ثالث. لا تكتب التوكن كرابط داخل المحادثات أو الكود.

### 5. تجربة الاتصال

Actions → مراقبة التعيينات → Run workflow → mode=`test-notification`.

المفروض تصلك: «🧪 هذا إشعار تجريبي لفحص الاتصال فقط. مو إعلان تعيين حقيقي.»

هذا يختبر توكنك والمحادثة والحفظ الدائم. لا يضيف إعلاناً وهمياً لقائمة الوظائف. إذا التشغيل أخضر لكن ما وصلت، راجع `bot-state/state.json`: قد تكون `uncertain` وتحتاج فحصاً يدوياً. الأخطاء لا تطبع التوكن.

### 6. فحص المصادر ثم التهيئة

1. شغّل mode=`check-sources` ليتحقق من بيئة GitHub نفسها؛ نجاح المصدر هنا مو مضمون من دولة/شبكة أخرى.
2. شغّل mode=`monitor`. أول تشغيل قد يأخذ دقائق لقراءة الأرشيف، وما يرسل دفعة الأخبار القديمة.
3. أرسل `/status` إلى البوت؛ سيجيب في مهمة المراقبة التالية.
4. بعدها تعمل الجدولة عند الدقيقة 7 و37 كل ساعة. لا تحتاج تبقي الهاتف متصلاً كي يستمر الفحص؛ تصلك الرسائل لما هاتفك يتصل بتيليگرام.

### 7. الأوامر

`/start`، `/help`، `/latest`، `/basra`، `/iraq`، `/today`، `/status`، `/search حاسوب`.

النتائج حتى 6 إعلانات في الرد. يعرض الإعلانات المؤكدة التي اكتُشفت بعد التهيئة؛ مو قائمة بكل الوظائف المتاحة الآن. لا يحذف الإعلان المنتهي من التاريخ تلقائياً؛ راجع الموعد الأصلي. الأزرار التفاعلية متوفرة. البوت يجيب Chat ID المحدد فقط؛ ليس بوت اشتراكات متعدد المستخدمين.

**الأوامر ليست فورية:** getUpdates يقرأ الرسائل خلال التشغيل المجدول فقط. قد تنتظر نصف ساعة أو أكثر عند تأخر GitHub. Telegram يحتفظ بالتحديثات حتى 24 ساعة؛ انقطاع أطول قد يفقد أوامر أو منشورات bot_api. تحتاج خدمة دائمة/خادم أو webhook لاستجابة فورية؛ غير مدّعى أنه يعمل هنا.

### 8. إضافة قنواتك

أرسل يوزرات القنوات مثل `@channel_name` حتى نفحصها. لا ترسل كلمات مرور حسابك أو أكواد تسجيل الدخول.

يدعم خيارين، على أساس صلاحية الوصول الفعلية:

- `public_preview`: قراءة النص من المعاينة العامة `https://t.me/s/USERNAME` إذا تسمح robots وبنية الصفحة. لا يتطلب حساب مستخدم أو جلسة شخصية. اليوزر وحده لا يضمن وجود معاينة أو السماح بقراءتها؛ إذا حُجبت يتوقف المصدر. يقرأ المنشورات الظاهرة فقط، وقد يفوّت منشورات كثيرة نُشرت بين الفحوص. الصور والفيديو وOCR غير مدعومة.
- `bot_api`: يشترط أن يسمح مالك القناة بإضافة بوتك إليها (عادة عبر صلاحيات إدارة القناة). **ما تقدر تراقب قناة شخص آخر بـBot API لمجرد معرفة يوزرها.** يستقبل ما ترسله Telegram للبوت من `channel_post` و`edited_channel_post`، ولا ينزل أرشيف القناة. أول دفعة متاحة وقت تهيئة bot_api صامتة.

تضاف القناة داخل `channels` في `sources.json`، مثلاً (هذه قناة توضيحية غير فعلية وليست مضافة افتراضياً):

```json
{
  "username": "@PUT_REAL_USERNAME_HERE",
  "enabled": true,
  "mode": "public_preview",
  "notify_news": true,
  "keyword_pattern": "تعيين|وظيف|عقد|درجات"
}
```

احذف `keyword_pattern` إذا تريد أي خبر جديد نصي من القناة. القائمة الحالية تحتوي 10 قنوات زوّد بها المستخدم، محفوظة وغير مفعلة إلى حين اختبار المعاينة من GitHub ومراجعة المحتوى. شبكة الفحص الحالية أعادت Site Unavailable؛ هذا لا يثبت أن القنوات محذوفة أو خاصة. جميع أخبار القنوات ترسل بعنوان «خبر قناة؛ مو تعيين حكومي مؤكد»، ولا تدخل /latest أو /basra كفرصة رسمية حتى يتحقق إعلان المصدر الحكومي مستقلاً. حتى القناة التي تقول إنها رسمية لا نمنحها صفة رسمية بمجرد اليوزر. لا يوجد فحص تلقائي للروابط الحكومية داخل منشور القناة في هذه النسخة.

### 9. إضافة مصدر رسمي جديد

1. ثبّت أن الموقع للجهة فعلاً، بدليل حكومي/روابطها الرسمية، وليس تشابه اسم أو لاحقة وحدها.
2. افتح robots وشروط الاستخدام. إذا لا يسمح أو تظهر CAPTCHA/حماية، لا تضف التفافاً؛ عطّله واكتب السبب.
3. حدّد صفحة قائمة تحتوي روابط أخبار فعلية وافحص مقالاً، نصه وتاريخه. RSS/API فقط إذا اكتُشف رابطها ووُثّق بناؤها. لا تفترض وجود `/feed` أو API.
4. انسخ بنية مصدر HTML في `sources.json` بمعرف جديد. عدّل `url` و`hosts` و`link_selector` و`link_pattern` و`title_selector` و`body_selector` و`date_selector`. لا تستخدم نص الصفحة كله لأنه يخلط قوائم وأخبار أخرى.
5. المصدر الوطني استخدم `province: null`؛ لا تفترض بغداد إذا لم تذكر. مصدر محلي ذو نطاق خدمة واضح يمكن تعيين محافظته مع توثيق السبب.
6. أضف نطاق مرفقات PDF إلى `hosts` فقط بعد التأكد منه؛ التحويلات خارج القائمة مرفوضة.
7. جرّب `python bot.py --check-sources` أو الوضع نفسه في Actions. ثم فعّل المصدر. أول فحص له صامت مثل بقية المصادر.

محوّل RSS يحتاج `kind: "rss"` ورابط RSS الحقيقي؛ يجلب المقال الأصلي بمحدداته المعتمدة. محوّل API يحتاج `kind: "api"` و`items_path` إن كانت القائمة متداخلة و`url_key` و`title_key` و`date_key`. `title_key` يشير حالياً لحقل نصي مباشر، وليس كائن WordPress rendered متداخلاً. لا يوجد API رسمي مفعّل في هذه الحزمة.

## حدود GitHub Actions والتكلفة

تحققت من وثائق GitHub الحالية وقت إعداد المشروع: standard GitHub-hosted runners للمستودعات العامة مجانية. الخاصة تستهلك الحصة/رصيد compute المضمن بخطتك، والتخزين له حصص أخرى. **لا أضمن رقماً ثابتاً لدقائق الخطة الخاصة**؛ صفحة الفوترة الحالية تتحدث عن included compute usage. راجع Billing الخاص بحسابك واضبط الميزانية/الحد قبل الاستعمال. لا تحتاج خادماً مدفوعاً لهذا التصميم.

- الجدولة تقريبية وقد تتأخر أو تُسقط مهمة أثناء الضغط؛ اختيرت 7 و37 لتجنب بداية الساعة. لا نضمن اكتشاف خلال 30 دقيقة بالضبط.
- نحو 1440 تشغيل خلال 30 يوماً؛ إذا كل تشغيل 2–3 دقائق فالمجموع نحو 2880–4320 دقيقة. هذا تقدير عبء، مو حصة مجانية مضمونة.
- ملف workflow يجب أن يكون على الفرع الافتراضي. في المستودعات العامة قد تُعطّل الجدولة بعد 60 يوماً بلا نشاط. راجعها دورياً؛ لا تعتمد على كتابات البوت كضمان لمنع التعطيل.
- للاستئناف: Actions → المراقبة → Enable workflow إذا ظهر تعطيل، ثم Run workflow يدوي. أضف نشاطاً مشروعاً مثل مراجعة المصادر وتحديثها. إعادة التفعيل لا تسترجع منشورات سقطت من صفحات المصادر أو تحديثات Telegram الأقدم من 24 ساعة.
- سجل الحالة محفوظ بين التشغيلات بفرع git. لا تستخدم cache أو artifacts كقاعدة بيانات. `cache: pip` لتثبيت الحزم فقط.
- المهمة محدودة بـ18 دقيقة، وبحد 12 رسالة مرسلة و300 تحديث Telegram لكل تشغيل. إذا توسعت المصادر أو المشتركين يحتاج التصميم تعديل.
- التزام واحد مؤقت أثناء إنشاء الفرع ثم سجلات الحالة لا يتطلب بيانات دفع ولا مفتاح خدمة مدفوعة. لا يوجد خادم فوري أو OCR أو جلسة Telegram شخصية مشمولة.

## الاختبارات والفحص المحلي

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python bot.py --check-sources
python bot.py --dry-run
```

`--dry-run` يفحص قائمة ومقالاً واحداً لكل مصدر بدون إرسال أو كتابة حالة؛ ليس محاكاة كاملة لدورة اكتشاف. ملفات الاختبار تستخدم بيانات اصطناعية محلية، ولا ترسل لتيليگرام. لتشغيل مراقبة محلية فعلياً ضع الأسرار كمتغيرات بيئة؛ الحالة المحلية `state.json` مستبعدة من git.

يوجد workflow للاختبارات على تغييرات الكود. الاختبارات تغطي منع التكرار وإعادة التشغيل والتغيير المهم والإعلانات القديمة/المجهولة وفشل الحفظ وانقطاع الإرسال والفرز وRSS/API والقنوات وحظر محادثات الآخرين. **لم يتم اختبار إرسال حي أو تخزين بمستودع مستخدم فعلي هنا لعدم وجود حساب/أسرار؛ يتم ذلك في الخطوتين 5 و6.**

## تحديث قائمة القنوات

تم حفظ 10 روابط مختلفة بعد حذف تكرار basrawebsite. راجع القائمة داخل `sources.json`. جميعها `enabled: false` و`verification_status: pending_github_check`؛ لم يتم اعتماد أي منها كمصدر حكومي رسمي.

شغّل mode=`check-sources` من GitHub: يشمل الآن اختبار معاينة كل قناة محفوظة حتى وهي معطلة، بدون إرسال أو تغيير سجل. بعد ظهور «معاينة ناجحة» ومراجعة أنها القناة المقصودة، غيّر `enabled` إلى `true` و`verification_status` إلى `preview_verified` للقنوات الناجحة فقط. اترك المتعذرة معطلة. لا يتجاوز البوت أي حماية. نتيجة الفحص غير الصفرية قد تعني فشل قناة حتى إن نجحت المواقع الحكومية.

فلتر أخبار القنوات مضبوط مبدئياً على كلمات التعيينات والوظائف والعقود. لا يصنّف الخبر كحكومي لمجرد مطابقته للكلمات. أول فحص بعد تفعيل القناة صامت؛ الإشعارات تخص المنشورات النصية الجديدة التي تظهر لاحقاً. لا توجد مراقبة فعلية قبل رفع النسخة المحدثة وإعداد Secrets وتشغيل المهمة.
